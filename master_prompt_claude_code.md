# Master Task Directive for Claude Code

**Role:** You are acting as a Senior Frontend Engineer, QA Specialist, and UX/UI Marketing Expert.
**Context:** You are tasked with executing a comprehensive UI/UX overhaul, bug-fix sprint, and i18n localization for `checkvisamap.com` (also branded as `gliddy`). We need to elevate this AI travel itinerary service from an MVP to a premium, high-conversion global product.
**Instructions:** Execute the following 5 phases thoroughly. Check all affected files, ensure strict TypeScript typing, and verify that the application builds successfully after your changes.

## Phase 1. Fix Markdown Rendering Bug ($$)
**Issue:** Sample itinerary pages occasionally display raw markdown and math symbol artifacts (e.g., `$$`, `\n`) generated by the LLM. This breaks the UI and lowers trust.
**Action Required:**
- Locate the component responsible for rendering the AI-generated itinerary strings (likely using `react-markdown` or a custom string renderer).
- Implement a robust pre-processing utility function to strip out unwanted LaTeX/math block artifacts (`$$` and `$`) before the string is passed to the markdown renderer.
  - *Regex Example:* `const cleanText = text.replace(/\$\$.*?\$\$/gs, '').replace(/\$.*?\$/g, '');`
- Verify that standard markdown elements (bolding, lists, H1-H3) still render perfectly.

## Phase 2. CTA UI/UX Conversion Redesign
**Issue:** The CTA section at the bottom of sample itineraries (currently a plain black box with text like "Yours, made the same way" or "내 플랜 만들기") is visually unappealing and fails to drive conversions.
**Action Required:**
- Locate the CTA section component.
- Completely rewrite the Tailwind CSS to create a premium, engaging design.
- **Background:** Implement a vibrant gradient or an elegant dark-mode glassmorphism card (e.g., `bg-gradient-to-br from-indigo-900 via-purple-900 to-black text-white shadow-2xl rounded-3xl`).
- **Button Design:** The button must demand attention. Use contrasting colors, large bold text, and hover micro-animations (e.g., `bg-white text-indigo-700 font-extrabold py-5 px-10 rounded-full shadow-[0_0_20px_rgba(255,255,255,0.3)] hover:shadow-[0_0_30px_rgba(255,255,255,0.5)] hover:-translate-y-1 hover:scale-105 transition-all duration-300`).
- **Layout:** Ensure generous padding and perfect responsiveness on mobile devices.

## Phase 4. Fix Hardcoded i18n Omissions (Header, Footer, Content)
**Issue:** When switching the site language to Korean, multiple UI elements remain stubbornly in English.
**Action Required:**
- **Footer Links:** Wrap "Terms of Service", "Privacy Policy", and "Refund Policy" in the `t()` function. Add keys to all locale files (e.g., "이용약관", "개인정보 처리방침", "환불 정책"). Ensure href routing respects the current locale.
- **Header Navigation:** Translate the top nav items: "Samples", "Pricing", "About", and the "Plan my trip" button.
- **Itinerary Metadata:** Localize tags within the sample pages: "4-day itinerary", "sight", "meal", "shopping" -> "명소", "맛집", "쇼핑".
- **Travel Toolkit:** Translate the affiliate links and section headers (e.g., "Travel toolkit for [City]", "Check rates on Agoda" -> "아고다에서 최저가 확인").

## Phase 5. UX Flow & Trust Improvements (New Discoveries)
**Issue:** A deep QA sweep revealed flow bottlenecks and branding inconsistencies that harm user trust.
**Action Required:**
- **Brand Consistency:** The domain is `checkvisamap.com` but the logo is `gliddy`. Unify meta tags, SEO titles, and footer copyright text to clearly define the brand relationship to avoid confusing users.
- **Loading State Localization:** The "While you wait" questionnaire loading screen currently displays "fun facts" and technical steps ("Indexing 240 restaurants...") entirely in English. Hook these strings up to the i18n system.
- **Navigation Dead-ends:** The `/plan/new` flow lacks a structural "Back" button. Users relying on the browser's back button risk losing their state. Implement a UI "Back" or "Previous Step" button in the questionnaire component.
- **Currency Clarity:** Prices are hardcoded as `$4`. Ensure this is explicitly clear and consider displaying the local currency equivalent (e.g., KRW) based on the locale, or adding a Stripe/Secure Checkout trust badge near the price.
