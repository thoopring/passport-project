## 1. L2 분석 (가장 크고 중요)

### 1.1 두 가지 분석 도구를 동시에 사용

**Google Analytics 4 (GA4)** — 이미 깔려 있던 거.
- 강점: 마케팅 출처(SEO/광고) 분석, 사용자 수, 머문 시간
- 무료
- 보는 곳: [analytics.google.com](https://analytics.google.com)
- 트래킹 ID: `G-3LF8H03QZG` (CLAUDE.md에 기록됨)

**PostHog** — 새로 추가. **선택 사항** (안 써도 GA4는 정상 작동).
- 강점: 깔때기(funnel), 코호트, 세션 리플레이
- 무료 티어 있음 (월 100만 이벤트까지)
- 보는 곳: [us.posthog.com](https://us.posthog.com)

**왜 둘 다?**
- GA4 = "사용자가 **어디서 왔는지**"
- PostHog = "사용자가 **사이트 안에서 뭘 했는지**"
- 합치면 풀 그림. 한쪽만 쓰면 반쪽짜리.

### 1.2 8개 이벤트가 뭘 추적하나

| 이벤트 | 언제 발생 | 알 수 있는 것 |
|---|---|---|
| `page_view` | 페이지 이동할 때마다 | 어떤 페이지가 인기인지 |
| `wizard_started` | 사용자가 여행 계획 만들기 시작 | 시작률 |
| `checkout_started` | "내 플랜 만들기" 눌러서 결제로 이동 | 결제 진입률 |
| `checkout_completed` | 결제 완료해서 플랜 받음 | **최종 전환률** |
| `account_signup` | 첫 매직링크 가입 | 가입 증가 |
| `account_visit` | `/account` 페이지 방문 | 재방문 |
| `referral_shared` | 공유 링크 복사 | 입소문 활동 |
| `credit_used` | 추천 크레딧/프로모 사용 | 보상 실효성 |

### 1.3 깔때기 예시

```
홈 페이지 봄 (page_view)         100명
        ↓
플랜 만들기 시작 (wizard_started) 30명  ← 30% 전환
        ↓
결제 시작 (checkout_started)      10명  ← 33% 전환
        ↓
결제 완료 (checkout_completed)    7명   ← 70% 전환
```

이런 그래프를 PostHog 대시보드에서 **클릭 몇 번이면** 만들 수 있어요. GA4에서도 가능하지만 더 번거로움.

### 1.4 로케일 태깅 = 핵심 가치

**모든 이벤트에 사용자 언어 정보가 자동으로 붙어요.**

예를 들어:
- "한국어 사용자의 결제 전환률 vs 영어 사용자의 전환률"
- "프랑스어 사용자가 일본어 사용자보다 wizard 중도 이탈이 많은가?"
- "어떤 언어 사용자가 추천 공유를 가장 많이 하나?"

이런 질문에 즉시 답할 수 있어요. 다국어 서비스에선 필수.

### 1.5 개인정보 안전장치

- PostHog 설정: `person_profiles: "identified_only"` — 로그인 안 한 사용자는 **익명 처리**
- 매직링크 인증 시점에만 `identify(userId, email)` 호출해서 그때부터 식별
- 비로그인 사용자 = 그냥 익명 ID만 추적

## 2. 추천 보상 — ⚠️ 알아야 할 갭

### 2.1 변경 내용

**전:** "공유하면 다음 플랜 무료" (친구가 사면 100% 무료 1건)
**후:** "공유하면 다음 플랜 25% 할인" (친구가 사면 다음 플랜 75% 가격)

5개 언어 전부 + 이메일 템플릿 + 공유 카드 + 계정 페이지 크레딧 안내까지 모두 변경됨.

### 2.2 ⚠️ 카피와 백엔드의 갭 (꼭 읽기)

**현재 상태: 보이는 메시지와 실제 동작이 다름.**

- 화면 안내: "25% off 받았어요" ✅
- 실제 사용 시: `plan_credits` 테이블에 크레딧이 있으면 LemonSqueezy 결제 자체를 건너뛰고 **100% 무료**로 플랜 생성 ❌

**즉, 사용자 입장에선:**
1. 친구가 가입 → "25% off 적립" 안내 받음
2. 사용 시도 → "어, 결제 페이지가 안 뜨네... 그냥 공짜네?" → 좋아함 (혼란할 수도)

**왜 갭이 생겼나:**
이번 작업은 **카피 정렬만** 했어요. 백엔드 메커니즘 변경은 LemonSqueezy 대시보드 작업 + 코드 변경이 더 필요해서 별도 작업으로 미뤘음.

### 2.3 정렬하는 3가지 옵션

#### 옵션 A — 진짜 25% off로 만들기 (추천)
1. **당신이** LemonSqueezy 대시보드에 25% 할인코드 생성 (예: `REFERRAL25`)
2. **나한테** 코드명 알려줌
3. **내가** 코드 변경: `plan_credits` 있을 때 → LS 결제 + 25% 코드 자동 적용
4. 결과: 친구 25% 받고 결제는 정상 진행 ($4 → $3)

#### 옵션 B — 다시 100% 무료로 카피 되돌리기
- 5분 작업
- 카피만 다시 free로 돌림
- 결과: 카피 = 메커니즘 = 100% 무료

#### 옵션 C — 그랜드파더링 (시간 들어감)
- 이미 발급된 크레딧 = 100% 무료 (계속 사용)
- 새 발급 크레딧 = 25% off 적용
- DB에 `discount_pct` 컬럼 추가 + 코드 분기 처리
- 약 2-3시간 작업

**→ A/B/C 중 어느 거 갈지 결정 필요. 결정하면 알려주세요.**
